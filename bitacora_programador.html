Stack: HTML + CSS + JavaScript (sin dependencias) · Artefacto claude.ai · 26 nov 2026
Resumen técnico

Página única autocontenida (un index.html, ~61 KB) con los 90 registros embebidos. Sin framework ni build. Persistencia en localStorage; exportación mediante la capacidad downloads del artefacto; importación JSON/CSV en el cliente.

Vanilla JSSin dependenciasSelf-contained localStorageCapability: downloadsContract 0.2.99

Objetivo

Dar al equipo de CESFAM Tongoy un seguimiento operativo de las 90 características del Estándar de Atención Abierta, que cargue sin instalación, se edite en vivo y sea 100% portable vía archivos (JSON/CSV/XLSX).

Arquitectura

Modelo de datos

Fuente de verdad embebida en const SEED = { meta, caracteristicas[] }. Cada característica:

{ id, ambito, ambito_nombre, componente, codigo,
  caracteristica, umbral_pct, umbral_texto, prioridad,
  estado, avance_pct, evidencia, responsable,
  fecha_revision, brecha, accion, observaciones }

Estado de la aplicación

Un objeto state = { inventario, caracteristicas[], updated }. El inventario mapea cada ámbito a true/false (presta / no presta).

Decisión central: override por inventarioEn lugar de duplicar el "No aplica" en cada fila, estadoEfectivo(c) deriva el estado: si el servicio del ámbito está en false, devuelve "No aplica"; si no, el estado guardado. Al apagar un servicio se guarda _prev para restaurar el estado real al reactivarlo. Una sola fuente, sin estados contradictorios.

Cálculo de métricas

metrics() aplica estadoEfectivo a todas las características, separa las aplicables (≠ "No aplica") y calcula el % de cumplimiento = Cumple / aplicables. El denominador excluye los "No aplica", en línea con el criterio acordado en el proyecto.

Persistencia

localStorage con debounce de 150 ms y try/catch: si el almacenamiento no está disponible, la UI avisa "usa Exportar" en lugar de fallar en silencio.

Importar / Exportar

Export JSON reconstruye {meta (+inventario), caracteristicas}; export CSV respeta el esquema con escape de comillas y BOM UTF-8. Import detecta JSON vs CSV por extensión y por el primer carácter; el CSV se parsea con una máquina de estados que maneja comillas y saltos de línea, y se cruza por codigo contra el SEED base (no se confía en el orden del archivo).

Decisiones y razones

DecisiónPor qué
Sin frameworkUn archivo, cero build, máxima longevidad. 90 filas no justifican React.
Datos embebidosLa herramienta funciona aunque no haya red ni archivo externo que cargar.
localStorage + exportCero backend; el usuario controla su respaldo. El JSON es el mecanismo de portabilidad y de trabajo compartido.
Capacidad downloadsEl visor de artefactos bloquea las descargas por enlace directo; claude.use("downloads") es la vía soportada, con respaldo a Blob.
Cruce por codigoHace el import idempotente y robusto a reordenamientos o filas faltantes.

Limitaciones conocidas y pendientes

En la lista • Seguimiento a nivel de característica, no de elemento medible (se puede anidar en una versión futura).
• Persistencia por navegador; la sincronización entre equipos es manual vía JSON (una versión con la capacidad db permitiría estado compartido).
• Falta el anexo de tamaños de muestra de la pauta para apoyar el cálculo de evaluaciones periódicas.

Cómo extenderla

Agregar o cambiar características

Editar el arreglo DATA del generador (gen_planilla.py) y regenerar JSON/CSV/XLSX; luego reconstruir index.html con build_app.py (que embebe el JSON) y republicar el artefacto.

Agregar un campo nuevo

Añadirlo al esquema en gen_planilla.py (FIELDS), al render de la tabla/detalle en build_app.py y, si debe exportarse en CSV, ya queda cubierto porque el CSV usa meta.campos.

Estado compartido entre viewers

Declarar la capacidad db y mover state.caracteristicas a filas en la base del artefacto; el patrón actual de import/export sirve de migración.
